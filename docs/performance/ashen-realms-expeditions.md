# ASHEN REALMS: 探索地形の性能予算

2026-09-14、Apple M5、Chrome 152.0.7977.83 / Metal、viewport 1280×900。
3D描画は既存の921,600ピクセル上限を使用。シード42、各240フレーム。
GPU時間は `timestamp-query`。CPUはCDPのTaskDuration増分を提出フレーム数で割った値。
CPUサンプリングプロファイルはフレーム計測の後に取得する。

静止シナリオのシミュレーションは一時停止し、描画を継続して比較する。
高台は隣接地域のチャンクと結合処理の完了を待つ。境界だけは実際に移動し、敵・ストリーミングも更新する。
スクリーンショット時は一時停止を解除するため、画像は計測終了後の場面である。

## 測定結果（生成器v3・植生と待機動作の追加後）

海岸・川・橋・岩窟、簡略化した隣接地域・島影・空に加え、バイオームの連続ブレンド、
不規則な林、追加の樹形と廃墟、草、TPSの遮蔽物透過、群れの待機姿勢を含む。
全8場面を同じビルドで再測定した。TPS透過は廃墟の壁越し、野営地は休息中の敵5体を表示する。
静止場面の待機姿勢は一時停止中の描画コストであり、警戒・戦闘中のCPU時間とは区別する。

| 場面 | CPU平均 ms/frame | GPU p95 ms | draw calls 中央値 | 提出インデックス数÷3 中央値 | RAF p95 / 最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 平坦な比較地形 | 2.65 | 1.94 | 64 | 57,116 | 16.7 / 16.8 |
| 探索地形・開始地点 | 3.16 | 2.13 | 80 | 47,940 | 16.7 / 16.8 |
| 高台と隣接地域 | 3.57 | 2.55 | 130 | 74,581 | 16.8 / 16.8 |
| 地域境界を移動 | 2.53 | 2.19 | 85 | 81,912 | 16.8 / 16.8 |
| 海岸と島影・TPS | 1.70 | 2.56 | 55 | 43,980 | 16.8 / 16.8 |
| 岩窟の内部 | 1.62 | 3.01 | 54 | 62,472 | 16.7 / 16.8 |
| 廃墟の遮蔽物透過・TPS | 1.75 | 2.49 | 61 | 78,900 | 16.7 / 16.8 |
| 休息中の野営地 | 2.61 | 2.53 | 81 | 82,144 | 16.7 / 16.8 |

インデックス数には地面・敵・小物・エフェクトなどが含まれるが、インスタンス数による乗算は含まない。
今回、共通プロファイラーも部分描画の実際のインデックス数を記録するよう修正した。
地面の詳細メッシュは **16,000三角形/地域**。遠景は地面・水面・ランドマークのシルエットを合わせて
**2,400三角形未満/地域**、世界の外の海・島・山並みは **6,500三角形未満**をテストで保証する。
空はKaguraの `draw3d` 共通部品に分離し、**12三角形・1 draw call**。テクスチャは使わない。
以前の背景に含めていた96三角形の空を置き換え、旧セーブ・地形実験でも表示する。

参考として、前回の生成器v2は開始地点CPU平均2.47ms、高台5.20ms、境界4.00msだった。
地形・構造物・可視範囲が変わっているため、同一場面での速度向上率を示す比較ではない。
高台では詳細な隣接チャンクも見えるため、簡略化後も130 draw callsを使用する。
全場面でJSエラーなし、境界の地域0→1の移動完了を確認した。

草は1チャンク80株・480三角形以下で既存の材質別バッチに含め、12〜25タイルで表示を減らす。
この距離処理はフラグメントの破棄であり、提出済みの頂点数を減らすものではない。
遠景には草を作らず、可視チャンクの外は従来のカリングを使う。
遮蔽物の透過は既存パスのディザ処理で、アルファ用の追加パスやメッシュ再構築はない。
待機・座位・立ち上がりはリグごとに48個のパレットを共有し、同じ姿勢の敵をインスタンス描画する。

この条件の計測区間ではRAF最大16.8msだった。ただし、下記の描画準備ピークは残る。
モバイルは表示・操作のE2Eを行ったが、実機GPUで同じ性能を測った結果ではない。
TPSの全方向・影/SSAOを有効にした場合・最大数の召喚戦闘までを、この表で保証しない。

## 遠景と詳細表示の切替

参考値として、2026-09-14にバイオームの連続ブレンドだけを追加した段階でも、同じ環境・240フレームで境界移動を測定した。
CPU平均 **3.36ms/frame**、GPU p95 **1.87ms**、draw calls中央値 **82**、
提出インデックス数÷3の中央値 **72,742**。地域0→1の移動完了、JSエラーなし。
地域生成最大10.0ms、チャンク準備7.1ms、材質別結合4.4ms、更新全体10.2msだった。
色は既存の近景・遠景メッシュの頂点シェーダーで補間する。重ね描き用の追加パスはなく、
植生の混在によって材質グループと三角形数が変わる。移動中の可視範囲も変わるため、
上表との差をブレンドだけのコストとは扱わない。

- 遠景用の地形は8タイル間隔。チャンク境界だけ細かい頂点を残し、近景と接合する。
- 遠景では木・草・小物・敵・物理オブジェクトを作らず、詳細地域の生成を要求しない。
- 4地域分の遠景は起動時にキャッシュ。移動中はインデックス範囲を変え、頂点を再結合・再転送しない。
- 近景が完成するまで遠景を残す。完成後は重なる遠景のチャンクだけを外す。
- 海面は大きな面で描き、背景と空を影・SSAOの入力から除外する。
- KaguraのWebGPUブリッジでインデックス範囲を保持し、同じGPUバッファを部分描画に再利用する。

## ストリーミングのピーク

境界シナリオは実際に地域0から1まで歩き、プリロード要求の開始から更新を追跡する。

| 工程 | 最大 ms |
| --- | ---: |
| 地域の地形・敵状態を生成 | 7.9 |
| 1チャンクの描画準備 | 8.1 |
| 2チャンクの材質別結合 | 4.2 |
| ゲーム更新全体 | 8.1 |
| 描画コールバック | 21.3 |

高台シナリオの準備中は1チャンク7.6msだった。表は全経路の最大値を保証するものではない。
最初の地形と描画メッシュの準備は約152〜159ms。これは起動時のコスト。
地形生成と最初のチャンクを同じ更新に重ねず、生成・チャンク作成・材質別結合を別更新に分配する。
隣接地域には、プリロード時に最大2チャンクずつ作る固定バッチを使う。
部分的にしか見えない組は元のチャンクを描く。

**移動中の描画準備に最大21.3msが残る。** アクティブ地域の可視メッシュ結合・アップロード準備が次の改善対象。
RAF統計と工程のピークは集計区間が異なるため、全工程が16.7ms以内とは解釈しない。
GPU常駐ジオメトリバッファの観測ピークは316本。これはメモリのバイト数ではない。
詳細地域のCPUメッシュキャッシュは最大3地域。遠景4地域分の静的メッシュは独立して保持する。

## 採用する表現の範囲

- 16,000三角形の高さマップ、ローポリの尾根・坂道、木・岩・廃墟・野営地。
- 川床と橋の歩行面、天井を別メッシュにした連続する岩窟、灯台。
- 粗い地形とランドマークのシルエット、霧と空のグラデーションで見せる遠景。
- 材質別静的バッチ、可視チャンクのカリング、1更新につき1つの背景生成工程。
- 密なSDF/voxel洞窟・動的侵食・高密度な草を増やす前に、アクティブ地域のメッシュ切替を改善する。

## 共通APIへの移行後の確認

同日、`camera3d` のブーム制御、`draw3d` の透過シェーダー、`terrain3d` の配置処理、
`scene3d` の手続き的な姿勢キャッシュへ移行し、8場面を再測定した。
**全場面でdraw calls・提出インデックス数の中央値が上表と一致した。**
CPU平均は1.96〜3.76ms/frame、GPU p95は1.40〜2.70ms、RAF最大16.8ms。
境界移動の描画コールバックには最大24.6msがあり、既存の一括準備の課題は残る。
透過の設定をパラメーター化したため、対象描画のuniformは68から72 dwordへ増える。
追加パスや頂点・インデックスの追加はない。

単発測定でCPU差が大きかった岩窟は、前コミット `e8dd4564` の独立worktreeと
移行後を交互に3回、各240フレーム測定した。CPU平均のrun間中央値は
移行前2.35ms（範囲1.70〜2.73ms）、移行後2.64ms（1.77〜2.94ms）。
測定帯が重なり、両方に時間経過に伴う上昇もあるため、速度向上・悪化は断定しない。
全runで54 draw calls・187,416インデックスを保ち、JSエラーはなかった。

実GPUのE2E 14件でTPS透過、群れの警戒、モバイルカメラ、橋・岩窟・空を確認した。
林のプレビュー画像は移行前とピクセル単位で一致した。待機中の姿勢やディザ境界には
撮影タイミング・演算の差が出るため、すべての場面の画素一致を保証するものではない。

## 再測定

```sh
just hunter-dev
just hunter-map-profile --out-dir output/expedition-profile
# 海岸のTPS視点だけ再測定
just hunter-map-profile --scenario panorama --out-dir output/coast-profile
# 遮蔽物の透過、休息中の野営地
just hunter-map-profile --scenario occlusion --out-dir output/occlusion-profile
just hunter-map-profile --scenario camp --out-dir output/camp-profile
```

出力は `summary.json`、各場面の `*.samples.json`、`*.cpuprofile`、プレイ画面のPNG。
生の計測はKagura共通の `measureWebPage` を使用し、ゲーム用スクリプトは場面・操作・保存先だけを定義する。
`preloadSamples` は最初のプリロード要求から更新を追跡する。準備完了後の平均だけを見てピークを落とさない。

共通コンポーネントのベンチとスキニングuniformの最適化結果は
[Landscape共通コンポーネントの計測](landscape-components.md)を参照。
