# FATHOM — 灯の届かぬ迷宮

Wizardryの方眼探索・6人パーティ・前衛と後衛・コマンド戦闘から着想を得た、短いオリジナルのダンジョンRPG。地下2階の守護者を倒し、「灯火の印章」を宿場へ持ち帰ると遠征達成です。

```sh
just dungeon-rpg-dev
# http://localhost:5198
```

ブラウザ版はWebGPUが必要です。Kagura StudioのExamplesから **FATHOM** を選んでも起動できます。マウス・キーボード・スマートフォンのタッチに対応します。

## 遊び方

1. 宿場で6人の隊列を確認し、迷宮へ入ります。仲間を2人選ぶと入れ替えられます。
2. 地図を埋めながら階段を探します。扉・宝箱・階段・出口は「調べる」で操作します。
3. 戦闘では敵カードで攻撃先を選び、各人の行動を入力します。全員分を確定するまで敵は動きません。「全員攻撃」はその場でラウンドを進めます。
4. 回復と火炎、回復薬を使い分け、地下2階の守護者に挑みます。
5. 印章を得たら地上へ戻ります。探索中の「帰還の鐘」でも帰れますが、戦利金が半分になります。

Web版はキーボード操作を基本に、迷宮と同じゲーム画面へ小さなコマンド一覧と冒険者の立ち絵・HPを重ねます。大きな操作パネルやページ全体のスクロールは使いません。地図と探索記録は **M** で開く手帳にまとめています。立ち絵のあるパーティ表示は世界樹の迷宮を参考にし、6人はオリジナルのデザインです。マウスでも選択でき、タッチ端末では移動ボタンを補います。

| 操作 | キーボード |
| --- | --- |
| 前進 / 後退 | W / S、↑ / ↓ |
| 左右に旋回 / 平行移動 | A / D、← / → / Q / E |
| メニューを選ぶ / 決定 | ↑ / ↓、Enter または Space |
| 調べる / 次のラウンド / 戦闘確定 | Enter |
| 戦闘の行動 | 1:攻撃、2:防御、3:治癒、4:火炎、5:回復薬、6:逃走 |
| 攻撃・回復の対象 | 行動選択後に矢印で対象を選び、Enterで決定。Escで戻る |
| 全員攻撃して確定 / 行動取消 | F / Backspace |
| 探索中の治癒 / 回復薬 / 帰還 | H / I / R |
| 宿場で隊列を変更 | G（またはメニュー4）→矢印とEnterで2人を選択。Escで戻る |
| 地図・探索記録 / 音 | M / V |

手帳を開いている間は移動・戦闘入力を受け付けません。MまたはEscで閉じます。TabでUIのボタンに移動する通常のキーボード操作も使えます。

待機・旋回・壁にぶつかる操作では灯りは減りません。歩くと1消費し、消えると敵との遭遇が早まります。「周囲の気配」は次の遭遇までの歩数です。入り口の近くは安全です。

前の3人が前衛、後ろの3人が後衛です。敵の近接攻撃は生きている前衛を狙います。後衛の通常攻撃は半減しますが、弓手は例外です。防御すると被害が半減し、護衛が防御すると、そのラウンドの単体攻撃を一度かばいます。全体攻撃はかばえません。戦闘不能は宿場の休息で回復します。

僧侶の治癒はMP2でHP12、魔術師の火炎はMP3で敵全体に6〜8ダメージ。回復薬はHP14を回復します。治癒・回復薬は探索中も使えます。コマンドの予約中にはMP・回復薬を消費せず、実行時に消費します。行動前に攻撃対象が倒れた場合は生存敵を狙い直します。

宿で休むとHP・MPが全快します（最大8G。所持金不足でも休めます）。宝箱は盗賊が生きていれば無傷で開けられます。祈りの灯は遠征ごとに一度だけ、生きている全員のHP6・MP2を回復します。全滅すると戦利金を失い、宿場へ救助されます。

## 保存と解析



宿場で隊列・レベル・HP/MP・所持金・回復薬・達成回数をブラウザのlocalStorageへ自動保存します。**探索途中の状態は保存しません**。再読み込みすると最後の宿場の記録へ戻ります。保存形式はschema 1で、読み込み時に人数・重複ID・数値範囲を全検証してから適用します。

Studioでは停止中の探索状態、隊列、HP・MP、敵HP、戦闘ラウンドを読み取れます。このゲームのフィールドは読み取り専用です。Studioの停止中はブラウザからのコマンドも受け付けません。

`just run-native dungeon_rpg` で起動するネイティブ版は簡易的な英語HUDとキーボード操作に対応します。Enterで出発・調査・次へ、WASD/QEで移動、1〜5で攻撃・防御・治癒・火炎・回復薬、Fで全員攻撃。治癒・回復薬は最もHPが低い生存者を選びます。宿場ではRで休息、Bで購入、探索中はRで帰還。隊列変更・永続保存・立ち絵・日本語UI・以下の画面演出はブラウザ版を使います。

## 画面演出

出発・階層移動・遭遇・勝利・帰還を短いフェードでつなぎます。攻撃には命中マークとダメージ数値、被弾には冒険者の点滅と画面端の赤い反応、防御には青、回復には緑の数値を使います。倒れた敵は結果確認中に薄い残像を残します。

通常の遷移は240〜320ms、歩行・旋回の反応は140ms。各命中表示は430ms、1ラウンド内の表示開始を最大500msの範囲でずらします。これはこの試作の調整値です。次のコマンドを入力すると演出を切り上げ、入力を待たせません。OSの「視差効果を減らす」設定では揺れ・移動・斬撃を使わず、遷移80msと数値表示180msを残します。

`sim/effects.mbt` のイベント記録は、実際のHP変化と対象IDを保持します。同じラウンドの複数の命中や、被弾後の回復を、HPの差分だけで推測せず表示します。記録は48件までで宿場のセーブには含めません。再生時計はゲームルールから独立し、Studio停止中は演出も停止します。

立ち絵アトラスはbuilt-inの `image_gen` で生成しています。[PNG](assets/party-atlas.png) / [最終生成プロンプト](assets/party-atlas.prompt.md)。透過を保持したまま6列のスプライトとして表示します。

## Jevによるautoplay


```sh
just dungeon-rpg-agent --dry-run           # 観測と合法手を確認。API不要
just dungeon-rpg-agent --seed 731          # 描画なしで1遠征を自動プレイ

# 画面を見ながら実行する場合（別ターミナルでdevを起動）
just dungeon-rpg-dev
just dungeon-rpg-agent --watch --seed 731

# 記録はAPIを呼ばずに検証・再生できる
just dungeon-rpg-agent --replay path/to/trace.jsonl
just dungeon-rpg-agent --replay path/to/trace.jsonl --watch
just dungeon-rpg-agent-test
```

`TYPESAFE_API_KEY`（または`TYPESAFEAI_API_KEY`）を環境変数へ設定します。未設定なら`~/.profile`の`TYPESAFE_API_KEY`のリテラル代入だけを読み取り、シェルは実行しません。キーはNode内に保持し、ゲーム画面や記録へ渡しません。`--watch`は独立したChromiumの保存領域を使うので、普段遊んでいるタブのセーブに干渉しません。ブラウザ未導入の場合は`pnpm exec playwright install chromium`を実行してください。

既存のカードゲームと[Jevのchoice API](https://api.typesafe.ai/openapi.json)への通信・応答検証を共通化しています。既定モデルは`jev-latest`。ゲームの観測と現在の合法手を送り、返されたIDとrevisionを検証してから通常と同じ`Game.command`を適用します。未発見の地形・乱数・seedはモデルの観測に含めません。探索では既知の経路上の目的地を選び、移動中に遭遇したら中断します。戦闘では各人の行動と対象を選び、全員分が揃うと確定します。「次へ」など選択肢が一つの操作はAPIを呼ばず自動適用し、記録で区別します。

既定の上限は300判断・120リクエスト（再試行を含む）・180秒。`--max-decisions`、`--max-requests`、`--max-seconds`で調整できます。実行中のCtrl-Cや期限超過は通信も中断し、`limit`として記録します。印章の持ち帰りだけが`victory`で、全滅は`defeat`、印章なしの帰還は`returned`、APIエラーは`error`です。Jev失敗時に別の自動操作へ切り替える処理はありません。

JSONLにはseed、各判断前後の観測、合法手、選択ID、確率・信頼度、実モデル名、時間と使用量を残します。出力先は`--out`で指定でき、既存ファイルは上書きしません。再生は全ての観測を比較するため、記録の欠損やルール変更による差異はエラーになります。判断回数や使用量は記録で比較できますが、Jevの再実行は同じseedでも同じ選択になるとは限りません。

2026-11-13の実API検証では、seed 731・初期6人で印章を持ち帰り、80判断（モデル69・自動11）/69リクエスト/約15秒で完走しました。同じJSONLを画面付きでも再生し、最終状態の一致を確認しています。これは1回の観測で、全seedの勝率を保証するものではありません。

`sim/agent.mbt`が合法手と適用、`sim/agent_observation.mbt`が観測、`agent_host/`が描画なしのFFI、`agent/`が通信・実行・再生のアダプターです。ブラウザ側の入口は`fathom.agent.observe()/step({revision,choiceId})/reset(seed)`。Studio停止中の変更は拒否します。共通通信は`scripts/agents/`にあり、他のゲームにも観測・合法手・stepを実装すれば接続できます。

## 構成と検証

- `sim/types.mbt`：状態・列挙型。`world.mbt`：迷宮・視界・灯り・宝箱。
- `sim/combat.mbt`：行動予約、素早さ順の解決、隊列と防御、報酬と成長。
- `sim/commands.mbt`：操作の検証と状態遷移。`effects.mbt`：命中・回復の表示コントラクト。`persistence.mbt`：宿場の保存コントラクト。
- `sim/snapshot.mbt`：表示・解析用DTO。ブラウザへは見えている地図だけを渡します。
- `sim/presentation_layout.mbt`：敵・名前表示・命中マークの共通の配置コントラクト。
- `view.mbt`：Scene APIの矩形でレイキャスト風の石壁とオリジナルのドット絵を描画。状態revisionまたは画面サイズが変わった時だけシーンを再構築します。
- `assets/host.mjs` / `style.css`：日本語HUD、入力、音、保存のアダプター。ゲームルールはMoonBit側に集約します。

```sh
just dungeon-rpg-test  # JS/nativeでロジックを検証
just dungeon-rpg-e2e   # Playwrightで実際のコマンド操作から帰還まで検証
just dungeon-rpg-ui    # dev起動中の画面をvlmkitで検証
```

テストには2層の経路到達、初期パーティによる守護者撃破・通常帰還・鐘での帰還、MP予約の取り消し、隊列、防御、全滅復帰、宝箱・祈りの一回性、壊れたセーブの拒否を含めます。E2Eは表示、描画領域内への収まり、クリアと保存復元、キーボードだけでの隊列・対象・呪文選択、演出の一回再生と中断、Studio停止、動きを減らす設定、スマートフォンのタッチを確認します。UI検査はGPU初期化・ホスト起動・立ち絵の読み込みを待ってから実行します（`tests/vlmkit-browser.mjs`）。操作可能性の検証であり、面白さの評価は実際に遊んで行います。

## 設計の基準と今後の調整

`sakurai-game-design`を参照し、主な判断を「さらに潜って報酬を増やすか、残りの灯り・HP・MPを見て帰るか」に置いています。[リスクとリターン](https://www.youtube.com/watch?v=cTSMohV3TgQ)を探索の核にし、[とにかくゲームさせてみて](https://www.youtube.com/watch?v=1toox93mCzs)に沿って宿場からすぐ出発できます。全滅後の宿泊費では再出発を塞がず、[リトライは迅速に](https://www.youtube.com/watch?v=xmQeUoKpTqg)を意識しました。具体的な数値はこの試作の仮設定です。命中の認識は[ヒットマーク](https://www.youtube.com/watch?v=8_muiV-JGuc)、短い遷移は[画面遷移は素早く](https://www.youtube.com/watch?v=yHZaki7FxjU)を参照しています。

現時点では固定の2層・固定の6人による一周分の試作です。装備、キャラクター作成、転職、属性、複数の呪文階梯はありません。敵の種類ごとの戦い方、探索の手掛かり、資源と成長の釣り合い、音・敵絵の演出は今後プレイしながら調整します。Wizardryの固有名詞・地図・文章・画像は使っていません。
