# プレイヤーのやりごたえとフィードバックを調べる自動調整

調査・実装日：2026-11-13。

今回の目的は、ゲームを正しく解くAIを作ることではない。プレイヤーが状況を読み、選び、その結果を受け取る過程にやりごたえがあるかを調べ、調整候補を作る。勝率や最適手の数だけでは、この目的を評価できない。

## 調査から採った判断

| 資料 | 確認した内容 | 今回の実装への判断 |
| --- | --- | --- |
| [Hunicke / Chapman: AI for Dynamic Difficulty Adjustment in Games](https://users.cs.northwestern.edu/~hunicke/pubs/Hamlet.pdf) | HPや弾薬などの供給・消費から、資源不足や不望なループを捉えるHamletの提案 | 勝敗だけでなく、消耗・回復・立て直しを記録する。論文の確率モデルを今回のRPGへそのまま移植したわけではない |
| [Booth: The AI Systems of Left 4 Dead](https://cdn.fastly.steamstatic.com/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf) | Directorのpacingは緊張の山の頻度を変え、難しさの振幅とは区別する（p91） | 敵の数値と、遭遇間隔・戦闘時間を別の軸として扱う。「敵HPを増やせばやりごたえが出る」とは決めない |
| [Politowskiほか: Assessing Video Game Balance using Autonomous Agents](https://arxiv.org/html/2304.08699) | エージェントによる比較を、難しさ・技能・偶然の分析に使う | 方針・seed・計測条件を固定して比較する。代理プレイヤーの結果を人間の楽しさに置き換えない |
| [RuleSmith v2](https://arxiv.org/html/2602.06232v2) | 合法手を検証するLLM self-playとパラメータ探索を分離。評価する集団への依存、人間への転移の限界も明記する | 実ゲームの操作契約を共用する。Jevの体験レビューは仮説として記録し、機械的な数値の目的関数と混ぜない |
| [Cohen-Solal / Cazenave: Minibal](https://arxiv.org/html/2603.23059v1) | ボードゲームで勝つ強さと、相手と釣り合うプレイを区別。定式化によっては意図的な僅差の敗北を選ぶことも議論する | 「均衡した勝率」を面白さと同一視しない。先後・戦略・役割別に結果を見る。意図的な敗北で数字を整える方式は採らない |
| [D&D Basic Rules 2018: Building Combat Encounters](https://media.wizards.com/2018/dnd/downloads/DnD_BasicRules_2018.pdf) | 単体の敵だけでなく、複数の敵、状況、休息や一日の資源消費を考慮する設計 | RPGの遠征と、カードゲームの単体戦闘を別の評価単位にする。D&Dの遭遇数や閾値を普遍的な基準とは扱わない |
| [Hansen: CMA Evolution Strategy Tutorial](https://arxiv.org/abs/1604.00772) / [differentiable_ecs](https://github.com/mizchi/differentiable_ecs) | 勾配を要求しない連続パラメータ探索 | 分岐・乱数・ターン制ルールを保ったまま、範囲内のパラメータを調べる |

`sakurai-game-design`の[リスクとリターン](https://www.youtube.com/watch?v=cTSMohV3TgQ)、[ゲーム性以外の面白さ](https://www.youtube.com/watch?v=OALp2UAe6V4)、[調整をしやすくする仕組み](https://www.youtube.com/watch?v=flVa8nHN_y0)も参照した。駆け引きだけで楽しさ全体を判断せず、変更を試して結果を見られる制作上の仕組みを整える、という基準で使っている。以下の数値は今回の仮設定で、桜井氏や論文の推奨値ではない。

## 評価を三つに分ける

1. **機械的な体験の証拠**：圧のあるラウンド、戦闘の長さ、回復と消耗、遊び方による結果の差。自動比較のための代理指標。
2. **フィードバックの対応**：実際のHP変化と命中・回復の表示記録、画面上の数値と対象、重なり、再生と終了。自動テストで確かめられる部分。
3. **プレイヤーが受け取るやりごたえ**：判断の意味を理解できたか、回復で立て直せたと感じたか、負けた理由に納得できるか、次を試したくなるか。画面や実プレイで判断する部分。

これらを一つの「面白さスコア」へ潰さない。整合性のない演出は他の良い指標で補償できない。逆に整合性が正しくても、読みづらい、単調、長い、といった問題は残りうる。

Jevにはプレイヤー役と、体験記録を読む役を用意した。後者は正解手順や勝敗を採点せず、緊張と回復、行動の結果が見えるかを判断する。記録にない映像・音・人の心理は未観測とする。モデルの自信は人間のやりごたえの実測値ではない。

## FATHOMで計測するもの

| 指標 | 意味と限界 |
| --- | --- |
| `pressureRoundRate` | 解決したラウンドのうち、実際に被弾した割合。注視や恐怖を測るものではない |
| `criticalRoundRate` | 生存者が最大HPの30%以下になったラウンド、または全滅したラウンドの割合。上限だけを置き、瀕死を強制する目標にはしない |
| `normalEncounterRounds` / `bossEncounterRounds` | 通常戦と守護者戦の長さ。長ければ良いとはしない |
| `recoveryShare` | 実際の被ダメージに対して、どれだけ回復が作用したか。回復の連打が楽しいと保証するものではない |
| 方針間のHP差 | 対処する遊び方と攻撃中心の遊び方の結果が違うか。正解戦略の定義ではなく、選択の効果の手掛かり |
| `feedbackMismatchRate` | HP変化と、対象・量を持つ命中・回復記録が一致しなかった割合。0を補償不能な条件とする |

ラウンド単位で計測する。6人分の入力の多さを、時間や緊張感の増加と取り違えない。被弾してから回復した同じラウンドは、最終HPの差分だけでは見えないため、個々のイベント記録を見る。全滅後に救助されHP1へ戻る処理や、レベルアップによるHP増加も区別する。

表示の検証では、同一対象への複数のダメージ数値の重なりが見つかった。命中記録の対象と量は正しくても、個々の反応が読み取りにくかったため、対象ごとに最大3行の配置へ修正した。デスクトップとスマートフォンで、実際の数値・対象・境界の重なりをPlaywrightで確認し、スクリーンショットも残している。

## ボードゲームとRPGへの適用

対戦ゲームは平均勝率だけで比較しない。先手・後手を交替し、同じ条件で試す。引き分け率や長期化も別の指標にし、「毎回引き分けるだけ」で均衡としない。方針間の有利不利は、ゲームが意図する駆け引きと照らす必要がある。

RPGでは、戦闘単体で残ったHPと、次の戦闘へ進める資源は違う。FATHOMは遠征全体で、カードゲームの今回のアダプターはFungiPairとの単体戦闘で計測する。カードゲームでは攻撃・防御などの方針ごとにターン数、使用カード数、消耗を見る。防御方針だけが長い消化戦にならないかもレビュー項目に含める。

アクションへ適用するときは、人間の反応・入力・視認に要する時間をゲーム側の下限にする。エージェントが即時反応できることを理由に予告時間を短縮しない。今回のターン制実装では反射速度を計測していない。

## 実装したループ

`differentiable_ecs`の現状は、微分可能なECSシミュレーションではなくCMA-ESの最適化ライブラリである。既存のハクスラの仕組みを確認したうえで、同じ公開版0.2.2のask/tellを非同期のautoplayへ接続した。上流ライブラリの変更は行っていない。

パラメータの上下限と刻みを定義し、探索用seedで候補を試す。基準値を必ず評価し、複数の方針・座席を区別する。探索終了後に、基準値と候補を未使用seedで比較する。検証が悪化した候補、フィードバック整合性に違反する候補、未完了の候補は出力しない。

実装の入口は[game/balance](../../game/balance/README.md)。今回実装したのは開発時の候補生成で、ゲームの途中に密かにHPや命中率を変えるDDAではない。FATHOMの設定は出発前だけ適用し、遠征中は固定する。

継続的なDDAへ進むときは、本人が選ぶ設定、次の遠征・遭遇などの適用境界、変更幅・冷却期間、固定難易度、対戦時の公平性を設計する。プレイヤーの上達や、意図的な危険の選択を打ち消す補正は避ける。

## 今回の観測

FATHOMは8探索seed×2方針で探索し、8つの未使用seed×2方針で比較した。944回の試行から、敵HP倍率1.4・攻撃倍率1.45・遭遇間隔8の候補を得た。検証側の対処方針では、通常戦は平均1.67→2.50ラウンド、被弾のあるラウンドは約63.5%→70.5%、表示記録との不一致は両方0だった。両方とも全遠征に成功しており、失敗を増やす目的の調整にはなっていない。全ての仮の目標範囲を満たしたわけでもない。

独立したJevで変更前後を1回ずつ遊び、体験記録もレビューした。両方ともクリアし、Jevは候補側で行動と状況の対応が強まる仮説を返した。これは1組の、モデル依存の推論に過ぎない。画面や音、人間の満足度の評価には数えない。

カードゲームは1224回の試行を行った。探索で良かった候補が未使用seedでわずかに悪化したため、プロファイルの出力を拒否した。こうした拒否も実験の結果として残す。

これらの結果から言えるのは、候補の生成・比較とフィードバックの検査が動作したことまでである。人間のやりごたえ、飽きやすさ、敗北への納得は未評価で、レビュー項目として残っている。
