# ASHEN REALMS: 探索地形の性能予算

2026-09-14、Apple M5、Chrome 152.0.7977.83 / Metal、viewport 1280×900。
3D描画は既存の921,600ピクセル上限を使用。シード42、各240フレーム。
GPU時間は `timestamp-query`。CPUはCDPのTaskDuration増分を提出フレーム数で割った値。
CPUサンプリングプロファイルはフレーム計測の後に取得する。

静止シナリオのシミュレーションは一時停止し、描画を継続して比較する。
高台は隣接地域のチャンクと結合処理の完了を待つ。境界だけは実際に移動し、敵・ストリーミングも更新する。
スクリーンショット時は一時停止を解除するため、画像は計測終了後の場面である。

## 測定結果（生成器v3）

海岸・川・橋・岩窟と、簡略化した隣接地域・島影・空を含む。
海岸は空を独立描画に変更した後、水平線が見えるTPS視点で再測定した。
他の5場面は独立描画へ変更する前の測定値。場面間の差を空だけのコストとは解釈しない。

| 場面 | CPU平均 ms/frame | GPU p95 ms | draw calls 中央値 | 提出インデックス数÷3 中央値 | RAF p95 / 最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 平坦な比較地形 | 2.30 | 1.91 | 62 | 52,440 | 16.7 / 16.8 |
| 探索地形・開始地点 | 2.31 | 1.99 | 74 | 44,120 | 16.7 / 16.8 |
| 高台と隣接地域 | 5.04 | 0.86 | 203 | 77,234 | 16.8 / 16.8 |
| 地域境界を移動 | 3.08 | 0.74 | 79 | 72,662 | 16.8 / 16.8 |
| 海岸と島影・TPS | 1.99 | 1.35 | 55 | 40,808 | 16.8 / 16.8 |
| 岩窟の内部 | 2.18 | 1.61 | 53 | 55,084 | 16.8 / 16.8 |

インデックス数には地面・敵・小物・エフェクトなどが含まれるが、インスタンス数による乗算は含まない。
今回、共通プロファイラーも部分描画の実際のインデックス数を記録するよう修正した。
地面の詳細メッシュは **16,000三角形/地域**。遠景は地面・水面・ランドマークのシルエットを合わせて
**2,400三角形未満/地域**、世界の外の海・島・山並みは **6,500三角形未満**をテストで保証する。
空はKaguraの `draw3d` 共通部品に分離し、**12三角形・1 draw call**。テクスチャは使わない。
以前の背景に含めていた96三角形の空を置き換え、旧セーブ・地形実験でも表示する。

参考として、前回の生成器v2は開始地点CPU平均2.47ms、高台5.20ms、境界4.00msだった。
地形・構造物・可視範囲が変わっているため、同一場面での速度向上率を示す比較ではない。
高台では詳細な隣接チャンクも見えるため、簡略化後も203 draw callsを使用する。

この条件の計測区間ではRAF最大16.8msだった。ただし、下記の描画準備ピークは残る。
モバイルは表示・操作のE2Eを行ったが、実機GPUで同じ性能を測った結果ではない。
TPSの全方向・影/SSAOを有効にした場合・最大数の召喚戦闘までを、この表で保証しない。

## 遠景と詳細表示の切替

- 遠景用の地形は8タイル間隔。チャンク境界だけ細かい頂点を残し、近景と接合する。
- 遠景では木・草・小物・敵・物理オブジェクトを作らず、詳細地域の生成を要求しない。
- 4地域分の遠景は起動時にキャッシュ。移動中はインデックス範囲を変え、頂点を再結合・再転送しない。
- 近景が完成するまで遠景を残す。完成後は重なる遠景のチャンクだけを外す。
- 海面は大きな面で描き、背景と空を影・SSAOの入力から除外する。
- KaguraのWebGPUブリッジでインデックス範囲を保持し、同じGPUバッファを部分描画に再利用する。

## ストリーミングのピーク

境界シナリオは実際に地域0から1まで歩き、プリロード要求の開始から更新を追跡する。

| 工程 | 最大 ms |
| --- | ---: |
| 地域の地形・敵状態を生成 | 10.0 |
| 1チャンクの描画準備 | 7.0 |
| 2チャンクの材質別結合 | 4.4 |
| ゲーム更新全体 | 10.2 |
| 描画コールバック | 25.3 |

高台シナリオの準備中には1チャンク11.5msも観測した。表は全経路の最大値を保証するものではない。
最初の地形と描画メッシュの準備は約136〜159ms。これは起動時のコスト。
地形生成と最初のチャンクを同じ更新に重ねず、生成・チャンク作成・材質別結合を別更新に分配する。
隣接地域には、プリロード時に最大2チャンクずつ作る固定バッチを使う。
部分的にしか見えない組は元のチャンクを描く。

**移動中の描画準備に最大25.3msが残る。** アクティブ地域の可視メッシュ結合・アップロード準備が次の改善対象。
RAF統計と工程のピークは集計区間が異なるため、全工程が16.7ms以内とは解釈しない。
GPU常駐ジオメトリバッファの観測ピークは290本。これはメモリのバイト数ではない。
詳細地域のCPUメッシュキャッシュは最大3地域。遠景4地域分の静的メッシュは独立して保持する。

## 採用する表現の範囲

- 16,000三角形の高さマップ、ローポリの尾根・坂道、木・岩・廃墟・野営地。
- 川床と橋の歩行面、天井を別メッシュにした連続する岩窟、灯台。
- 粗い地形とランドマークのシルエット、霧と空のグラデーションで見せる遠景。
- 材質別静的バッチ、可視チャンクのカリング、1更新につき1つの背景生成工程。
- 密なSDF/voxel洞窟・動的侵食・高密度な草を増やす前に、アクティブ地域のメッシュ切替を改善する。

## 再測定

```sh
just hunter-dev
just hunter-map-profile --out-dir output/expedition-profile
# 海岸のTPS視点だけ再測定
just hunter-map-profile --scenario panorama --out-dir output/coast-profile
```

出力は `summary.json`、各場面の `*.samples.json`、`*.cpuprofile`、プレイ画面のPNG。
生の計測はKagura共通の `measureWebPage` を使用し、ゲーム用スクリプトは場面・操作・保存先だけを定義する。
`preloadSamples` は最初のプリロード要求から更新を追跡する。準備完了後の平均だけを見てピークを落とさない。
