# Landscape共通コンポーネントのベンチと最適化

2026-09-14。Apple M5 / macOS arm64、Node v24.21.0、Moon 0.1.20260904。
対象は共通APIへの移行後の状態と、`draw3d` のスキニングuniform生成を最適化した状態。
ゲームや地形の内容を変えず、同じconsumer fixtureを両方のcheckoutに置いて比較した。

## 測定方法

`just bench-paired --baseline-dir /path/to/before --runs 3 --out-dir output/landscape-paired`

既存bench-gateと同じworkspace rootの `moon bench --target js` を旧→新の順に3組実行。
計測中に別のビルド・テスト・ブラウザプロファイルを走らせていない。
以下は各runの平均値3個の中央値と最小〜最大。package-localの探索用測定は含まない。
ベンチの処理量・計測範囲は [fixtureの説明](../../benchmarks/landscape/README.md)、
全サンプルと環境は [JSON](landscape-components-bench.json) に保存した。

## 採用した変更

`new_skinned_lit_mesh_draw_command` と
`skinned_instanced_monochrome_lit_uniform_dwords` で、最終サイズのゼロ初期化配列を
一度だけ作り、有効な行列・照明・色をオフセット指定で書き込む。
小刻みな `push` による拡張と、未使用の骨・インスタンスを埋める追加ループを省いた。
既存APIのまま利用でき、コマンド間で可変のuniform配列を共有しない。

通常描画1,084 dword、単色インスタンス描画2,088 dwordのABIは維持する。
`skinning_uniform_wbtest.mbt` の追加前は未実装のwriter契約で失敗することを確認し、
実装後は境界付き書き込み・全dword一致・別コマンドの独立性を確認した。
骨数0/1/18/63/64/65、インスタンス数0/1/8/64/65を含み、
従来の上限超過時のcount表現も変更していない。

比較runnerは全サンプルを保存し、項目の欠落・重複・無効な値で失敗する。
帯の重なりを中央値の比だけで隠さない。これらはNodeのテストで固定した。

## ゲームでの確認

`just hunter-map-profile` の8場面をChrome 152 / Metal、1280×900で実行した。
全場面でJSエラーなし。7場面は最適化前の記録とdraw calls・インデックス数が一致した。
平地は69 draw calls / 173,544インデックスで、以前の64 / 171,348と異なるため、
全体の性能比較には使わない。ゲームを起動後にpauseするこの場面は停止タイミングで
敵の表示状態が変わりうるため、描画量も一緒に記録する。

野営地は同じベンチ前後のcheckoutを別ポートで配信し、旧→新を3組、各240フレーム測定。
CPU平均のrun間中央値は **3.85→3.30ms/frame（14.3%短縮）**。
変更前の範囲3.79〜3.97ms、変更後2.33〜3.43msで全runの帯が分離した。
全runで **81 draw calls / 246,432インデックス**、JSエラーなし。
GPU p95は旧2.42〜3.01ms、新1.46〜3.06msで重なっており、GPUの改善は断定しない。
CPUの改善率はこの場面・環境に限る。ブラウザの各回の値も上記JSONに保存した。

地域境界の描画コールバックには最大30.6ms、RAFには33.4msが残った。
既存の可視メッシュ結合・アップロード準備のピークを今回のuniform最適化で
解消したとは扱わない。その他7場面のRAF最大は16.8msだった。
