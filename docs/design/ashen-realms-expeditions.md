# ASHEN REALMS: 探索進行から生成する地形

新規セーブでは、海岸・川・山腹を持つ世界に、補給路と高台の報酬を結ぶ探索グラフを埋め込む。
生成器v3は、石の列で囲った境界を海・支流・山の斜面に置き換える。
ノイズはグラフの周囲の尾根を変えるために使い、道路・戦闘広場・報酬地点の高さを先に与える。
今回のメタプログレッションは **セーブごとに永続する探索・帰還地点の解放**。
アカウント共通の能力強化や、死亡でリセットする周回構造は導入していない。

## 遊びの構造

- 低地: 幅の広い街道、集団戦の野営地、装備と回復。
- 高台: 坂道を登った廃墟・礼拝堂、遠距離の敵を含む守備隊、レア装備。
- 支線を上側・下側のループで接続し、往復だけの寄り道を減らす。
- 宝箱を開けると、その場所が帰還地点になる。灯火または解放済みの帰還地点から、
  `G` の世界地図で移動する。地域の灯火にも戻れる。
- 地点の解放、宝箱、倒した敵、地面のアイテムは保存する。死亡時は従来どおり地域の灯火で復帰。
- 地図は実際の高さを色分けし、生成した道路、各拠点の高さ・報酬・解放状態を示す。
  PC・タッチ・ゲームパッドの選択操作を共通のゲーム側コマンドへ送る。

拠点は既存の5広場・4宝箱の識別子と位置を保つ。シードで接続点・標高・局所地形が変わり、
地域ごとに Hybrid / Voronoi / Perlin / Diamond Square を使い分ける。
**拠点の空間配置そのものを毎回再抽選する生成器ではない。**
上位グラフを先に置く構成を導入し、既存の敵・装備・保存処理と一緒に遊べる範囲を実装した。

## 自然の境界とプレファブ（生成器v3）

- 西と南は海。海岸線の先には島影と海面を続け、地面の長方形の端を見せない。
- 蛇行する川と、地域境界を横切る支流。街道との交点から木橋を作り、分岐は乾いた岸に置く。
- 北・東と地域間の稜線は斜面。峠道の切れ目から次の地域へ歩いて移動する。
- 木橋は床板・手すり・橋脚・筋交いを持つパラメトリックなプレファブ。川床と歩行面は別の高さ。
- 山腹には二つの入口を持つ岩窟を置く。通路・敵・プレイヤーは同じ連続したグリッドで動き、ロード画面を挟まない。
  見下ろし視点で通路に入ると天井だけを外す。TPSでは天井を残す。
- 海辺の灯台、既存の宿場跡・礼拝堂・野営地を目印に使う。旧道の壊れた荷車は橋を塞がない場所へ移す。
- 地図に水域・橋・抜け洞窟・灯台を表示する。

## 実装の境界

| 層 | 所有するもの |
| --- | --- |
| `game/terrain3d/graded_routes.mbt` | `TerrainPad`、`TerrainRoute`、道路の高さの補間、地面へのブレンド、三角形の勾配 |
| ゲームの `game/expedition.mbt` | シード付き探索グラフ、拠点の役割・標高、ノイズの適用、道路配置 |
| `game/landscape.mbt` | ワールド座標の川・海・山、橋の契約、川床と歩行面、自然物の移動マスク、v3の探索グラフ |
| `app/landscape_prefabs.mbt` | 木橋、岩窟、灯台の近景モデル |
| `app/landscape_lod.mbt` | 地域の簡略メッシュ・遠景。静的バッファとチャンクごとのインデックス範囲 |
| `game/expedition_validation.mbt` | 宝箱と地域出口への経路探索、歩行面の最大勾配、三角形・衝突タイル数 |
| `game/expedition_progress.mbt` | 帰還地点の利用条件、解放済み地点への移動 |
| `app/expedition_map.mbt` | 地形から作る地図のキャッシュ。経路探索・等高色生成は毎フレーム行わない |
| `draw3d/sky.mbt` + `app/sky.mbt` | 地形と独立した空。地平線・上空・雲・太陽の色、カメラに追従する12三角形 |
| `app/world_streaming.mbt` | 地域メッシュの保持、1更新につき1つの生成／チャンク／結合作業 |

地面は1地域100×80セル、16,000三角形。表現を増やすために地面の解像度は増やしていない。
ローポリの面法線と、標高・勾配に応じた岩肌の材質で地形を見せる。
舗装の破片、街道の小石、ウェイポイントも同じ地形に接地させる。

道路と戦闘エリアを `limit_slope(0.45)` で整え、その後に川床と山の斜面を作る。
急な地形（勾配0.72超）と水域は歩行不可。橋では川床の上に元の歩行面を残し、床板と接地を同じサンプルから作る。
水辺の見た目とコリジョンを同じ `LandscapeKind` から決めるため、境界の岩モデルは不要。
重複する3頂点列では、ワールド座標の地形と共通の橋の高さを使用して生成順によらず一致させる。

ジャンプは実装していない。全必須地点と洞窟の両入口を徒歩でつなぐ。
橋の下は水域で通行しないため、同じXZ地点に複数の歩行レイヤーは持たない。
洞窟は高さ場の通路に別の天井メッシュを被せた岩窟で、Voxelを掘削する方式ではない。
戦闘の命中判定は既存のXZ平面を基礎とする。

## 遠景の描画予算

地域の遠景は8タイル間隔の地形、海面、灯台と岩窟のシルエットのみ。木・草・小物・敵・物理オブジェクトを作らない。
チャンク境界だけ1タイル間隔の頂点を残し、詳細メッシュとの接合位置を合わせる。
静的な1組の頂点・インデックスバッファに地域内のチャンクを並べ、詳細表示する範囲を除いて連続した範囲をまとめて描く。
隣接地域の詳細メッシュが未完成でも簡略地形を表示し続ける。詳細の準備と遠景表示は独立している。

遠景は4地域分を起動時にキャッシュし、カメラ移動では再生成・再結合・頂点転送をしない。
テスト予算は1地域2,400三角形未満、海・島・山並みの背景は6,500三角形未満。空は別に12三角形・1 draw call。
背景と空は影・SSAOの入力から除外する。海面は領域ごとの大きな面で表現する。

空は地形生成器と切り離し、旧セーブ・地形実験でも描く。カメラに追従する内向きの立方体に、
方向に応じた空の色・薄い雲・太陽を描き、テクスチャや背景用の敵状態を持たない。
クリップ境界付近の補間で欠けないよう、頂点は境界の内側に置き、フラグメントで遠端の深度を出力する。

kaguraのWebGPU共通処理も修正した。深度アタッチメントは明示された頂点strideを優先し、WGSLの変数名に依存しない。
`DrawTrianglesCommand.index_offset` とインデックス数をJSブリッジからGPUまで保持する。
部分描画も同じGPUバッファを共有し、プロファイラーは実際に送る範囲のインデックス数を数える。

## 植生・視認性・群れの待機

`game/woodland.mbt` は座標ハッシュと歪めた密度場から木の候補を選び、
近隣で優先度が最も高い候補だけを残す。道路・広場は従来の整形段階で確保する。
`app/woodland_scenery.mbt` が樹形、草の配置条件、尖頭アーチ・巡礼者像・倒壊柱のメッシュを持つ。
草は材質別バッチに結合し、1チャンク80株・480三角形以下。遠距離ではフラグメントを破棄する。
木を再配置した地図の読み込みでは、障害物と重なる敵・戦利品を安全な場所へ補正し、プレイヤーは灯火へ戻す。

TPSのカメラは地面をブームで検査し、木や建物の2D衝突マスでは縮めない。
`app/camera_visibility.mbt` が視点・プレイヤーの中心・表示タグをシェーダーへ渡す。
その間の遮蔽物だけをディザ透過し、アルファ用のソート・重ね描き・動的なメッシュ再構築を避ける。
タグは地形・遮蔽物・草を区別し、近景と隣接地域で共有する。地面への衝突は即時、復帰は緩やかにする。

敵は `EnemyCamp` に群れのID、待機姿勢、`Resting / Waking / Alert` の状態を持つ。
野営地か広場ごとに所属を固定し、移動した敵を毎フレーム距離で再編成しない。
6.5タイル以内の視線が通る接近、召喚ゾンビの接近、被弾を群れの刺激とする。
立ち上がる36フレーム中は攻撃を開始せず、方向も徐々に変える。警戒済みの群れが遠くへ行くと足踏みせず待機する。
姿勢は `app/idle_motion.mbt` の48個の共有パレットを使い、足を動かさない呼吸、座位、狼の伏せ、立ち上がりを描く。
保存した警戒状態は復元し、旧セーブには群れを割り当てる。既に負傷した敵は警戒状態で復元する。

## 保存と互換性

探索地形の平地は `plains_relief`（0〜1）で調整できる。0では拠点の標高を
逆距離の重みで滑らかに補間した地形、1では従来のノイズと標高を使い、その間を連続的に混ぜる。
道路・高台・川・海・橋・岩窟は後段で整形する。`N` →「探索地形」にスライダーと35%プリセットを置く。
変更時は準備済み地域の地面と衝突を作り直し、近景・隣接地域・遠景のキャッシュを更新する。
敵・宝箱・戦利品の進行は保持し、地形変更で障害物と重なる場合だけ安全な位置に補正する。

バイオームの色は `app/biomes.mbt` のワールド座標の移行帯で補間する。
地域境界を中心に約40タイルの帯を蛇行させ、4地域の色を頂点シェーダーで混ぜる。
近景・隣接地域・遠景は同じシェーダーと座標系を使う。植生の種類も同じ重みから選ぶ。
マテリアル番号を既存頂点のUV領域に保存するため、ブレンド用の地面・テクスチャ・draw callは増えない。

ワールド保存形式はversion 4、生成器は `generator_version: 3`。
生成器番号を持たない旧形式はversion 1、version 2の保存は旧探索地形で復元する。旧セーブの標高や進行構造を勝手に入れ替えない。
未訪問地域の生成にも保存された生成器番号を使う。不明な生成器番号は拒否する。
`plains_relief` はワールドの保存に追加し、項目がない旧セーブは1として従来の形状を復元する。
宝箱の `opened_chests` が帰還地点の永続状態で、別の重複した解放フラグを保存しない。

地形実験 `N` の「探索地形」で通常の生成結果に戻せる。
実験用ノイズのパラメータとワールドの探索シードは別管理。
生成器version 1では探索地形への切替ボタンを無効にする。version 2・3では、それぞれ保存された通常地形へ戻す。実験モード中は自然地形のマスクを外して共通の実験用グリッドを使う。

just hunter-dev

  landscape.spec.ts expedition.spec.ts world-map.spec.ts exploration.spec.ts terrain.spec.ts

部分的に見えるチャンクの厳密なカリングと、視点変更時に再結合しないことを検証する。

## 調査を踏まえた選択

行動と報酬の構造を先に定義し、配置へ落とす方針は、
[Linden, Lopes, Bidarra: Designing Procedurally Generated Levels](https://ojs.aaai.org/index.php/AIIDE/article/view/12592)
のaction graphの考え方を参考にした。今回は汎用のグラフ文法エンジンを導入せず、ゲーム側に小さなグラフ生成規則を置く。

[WFCの原実装](https://github.com/mxgmn/WaveFunctionCollapse)は局所的な隣接・作例整合性を扱う。
今回の到達性・ループ・帰還地点は別層で定義し、WFCは建物や局所装飾を増やす段階の候補とする。

[Transvoxel](https://transvoxel.org/)は異なる解像度のボクセルメッシュの継ぎ目を処理する技術。
今回の高さマップには不要であり、洞窟・オーバーハングを本当に遊びに使う段階で検討する。
