# Ember Ascent: 開始フローとイベント後の進行

キャラクターを選ぶと第1幕のマップから通常ランを開始する。Act選択画面と、その画面だけで使っていたエージェントの選択肢を削除した。CLIから第2幕・ボス戦を直接起動するシミュレーション機能は引き続き使える。

イベントの効果を確定した後、ランはすでに次の接続先を選べる状態に戻っていた。ただしヘッダーが完了した階のままで、現在マスにも完了表示がなく、進んでいないように見えた。マップのヘッダーを `NEXT FLOOR` に変更し、完了した現在マスを `DONE` と表示する。イベントのデバッグfixtureも、実際に1階の戦闘と報酬を経て2階のイベントへ入る状態に変更した。

画面のイベント選択肢数を固定値から実際の選択肢数に変更し、描画とポインターの判定で同じレイアウトを使う。現行の4イベントはすべて3択で、選べない効果・二重取得の拒否は既存の共有ロジックが担う。

## 検証

- Red: 画面／エージェントの開始フロー、イベント完了表示の3テストが変更前に失敗。
- Green: MoonBit JS／nativeで各200テスト成功。4種類のイベントを完了し、640×440のポインター操作で次の接続先に進める。
- Jevのホスト／Node契約を検証し、キャラクター確定後に第1幕の合法な3マスが提示されることを確認。
- Playwrightの30テスト成功。PC・スマホの実際のイベントマスをクリックし、イベントを完了して3階に入れることを確認。
- 公開用releaseビルドでPC・スマホ各1回、開始画面から最初の戦闘をクリアし、報酬スキップ、イベント選択・完了、3階への進行まで操作。debug fixtureは使用しない。
- 40状態×5サイズの200キャプチャでvlmkitと配置・コントラストの検査が成功。意図した25画像だけを確認して更新し、200枚すべてが現在のキャプチャとバイト単位で一致。Act選択の5画像をイベント完了後の5画像で置き換えた。
- releaseビルドのマップ・戦闘・イベント・イベント完了後を各2幅、計8枚でvlmkitと配置・コントラスト検査が成功。
- 根本のフレーム回帰検査は、開始ボタンの説明文変更だけが差分。確認した1枚を更新し、差分なしを再確認。
- Nodeスクリプト328テスト、Pagesカタログ13テスト、CLIの埋め込みランタイム整合性検査が成功。

前のリリースで失敗していたテーマ検査は、旧UIのパレット定義が残っていたことが原因。現行UIの色と合成後の色に定義を合わせ、テーマ検査も成功した。
